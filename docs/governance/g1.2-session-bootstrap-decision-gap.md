# G1.2 — Session trust-purpose decision gap

Estado: `SUPERSEDED — decisión materializada; evidencia runtime pendiente`
Fecha del análisis original: 2026-09-17

> Este documento conserva el hallazgo previo a la ratificación. La contradicción documental descrita aquí ya no bloquea la implementación. La fuente vigente es `g1.2-session-bootstrap-implementation-gate.md` y `g1.2-session-bootstrap-execution-2026-09-17.md`.

## Decisión materializada

La superficie de firma de sesión usa el propósito canónico:

```text
SESSION_ASSERTION
```

La autoridad de emisión es central; el POS sólo confía en claves públicas operacionales firmadas por el root de producto. `DEVICE_TRUST`, `MASTER_SNAPSHOT`, licencia y actualización permanecen separados por propósito.

## Distribución materializada

El producto contiene un root público fuera de la cadena de secretos privados y un bundle operacional firmado. El Local Service recibe la ruta del bundle mediante configuración validada, verifica root, propósito, environment, vigencia y estado, y persiste el bundle en el almacén protegido.

Las actualizaciones del bundle son monotónicas por `version`: un artefacto anterior no puede hacer rollback del trust store y una misma versión con contenido diferente se rechaza.

## Runtime materializado

`main.ts` resuelve el trust material antes de construir `CommercialComponent` y entrega el mapa resuelto al `SessionAssertionVerifier`. La ruta de sesión continúa siendo:

```text
session.activate
  → SessionAssertionVerifier
  → SessionAssertionStore
```

## Evidencia que sigue pendiente

- ejecución observable del servicio Windows real;
- caller real por named pipe;
- recuperación después de reinicio;
- rotación/revocación ejecutada en runtime.

No se declara `RUNTIME_VERIFIED` hasta observar esa ejecución.
